# writeAlizer audit — 16 September 2026

The audit covered all eight R source files, exported functions, internal loaders,
the 50-row artifact registry (38 unique files), tests and test helpers, maintenance
scripts, package metadata, CI configuration, README, both vignettes, and function
reference documentation. Confirmed implementation bugs were fixed. Existing model
formulas, training artifacts, preprocessing methods, aliases, and valid output
column names were preserved.

## Findings and resolutions

| Priority | Finding and consequence | Resolution and evidence |
|---|---|---|
| High | CSV type inference changed IDs such as `001` into `1`, which could misidentify texts or create incorrect matches. | Read identifiers as text before numeric conversion. Regression tests cover all three importers, sorting, blanks, and leading zeros. |
| High | Prediction assignment could recycle a short result or silently discard extra prediction columns. | Require one prediction per input row; accept one-column matrices/data frames and validate preprocessing ID order. Tests cover vectors, matrices, data frames, lists, arrays, wrong lengths, and reordered rows. |
| High | Transfer return codes were ignored and unverified downloads replaced cached files. A failed copy could appear successful; a bad checksum left bad bytes in the cache. | Stage on the cache filesystem, check copy/download/rename results, verify before publishing, and clean staging files. Tests demonstrate retries, preserved old files, rejected bad checksums, and failed cache writes. |
| Medium | Standard POSIX `file:///tmp/...` URLs lost their leading slash. Existing tests often used an extra slash that concealed this. The Windows UNC parser also lost its network prefix. | Use a shared parser with deterministic POSIX, Windows-drive, UNC, localhost, and encoded-space cases. Exercise actual local file downloads. |
| Medium | Imports accepted missing/blank IDs and ambiguous ID columns, selected required columns before validation, and allowed duplicate CSV headers to be silently renamed. | Validate before renaming, selection, or arithmetic; reject ambiguous identifiers and headers. Keep blank/NaN feature measurements as missing numeric values and preserve `#` in ReaderBench IDs. |
| Medium | Invalid model keys could trigger registry/loader errors before the intended model-key error. Variable lists and prediction inputs were insufficiently checked. | Validate models first, then data, required numeric features, variable-list contents, and part counts. Existing scoring behavior is covered with regression tests. |
| Medium | One model loader ignored registry checksums; empty fit archives produced low-level indexing errors; nested ensemble dependencies were missed. | Propagate checksums, reject empty archives clearly, and inspect nested caret model dependencies. Tests use real local archives and missing-package fixtures. |
| Medium | Registry and path options accepted malformed values; retry counts accepted non-finite/fractional numbers; filenames could escape their cache directory through `..`. | Validate option scalars, registry rows/parts, relative filenames, hashes, and retries before file access. Empty/NA checksum fields mean no checksum. |
| Medium | The internal compatibility varlist loader missed `_vars_v2.rds` names and did not canonicalize legacy keys. | Recognize v2 names, canonicalize aliases, and use the configured registry accessor. |
| Medium | Tests could delete the real user cache. Several mocks had the wrong lifetime, and a loader test skipped when it should have failed. | Isolate the entire suite under a temporary cache root; use package-scoped mocks; remove unnecessary skips and replace the loader skip with assertions. The full suite passes without skips. |
| Medium | The checksum maintenance script referenced removed `.wa_artifacts()` and could establish checksums from stale cached files. | Read the shipped registry, download into a fresh temporary cache, restore options, and only write the registry after all rows succeed. This maintenance operation was reviewed but not run, because it deliberately replaces release checksums. |
| Medium | Documentation named nonexistent output columns, described all optional packages as installed, overstated cache prompting, and gave an encoding example that did not transcode text. | Correct model tables, dependency guidance, cache instructions, and UTF-8 conversion; validate examples during package checks. |
| Low | Examples could leave global options changed or write into the real cache; the seed helper claimed it could only write under `tempdir()`. | Use local scopes and temporary directories, restore settings, and describe the supplied directory accurately. |
| Low | Cache previews included directory sizes in the reported file size. | Sum file sizes only; test empty, normal, and unavailable-size previews. |
| Low | R and testthat minimum versions did not match APIs already in use. | Declare R >= 4.0.0 and testthat >= 3.2.0 in DESCRIPTION and codemeta. |

## Documentation and presentation

- Reorganized introductory content around choosing a model, installing, trying a
  sample, importing personal data, understanding results, and saving scores.
  Detailed analysis-program setup remains available with screenshots.
- Kept a practical, welcoming tone, defined scoring abbreviations, separated
  executable commands from illustrative output, and added troubleshooting.
- Split model tables by analysis program, listed recommended models first, and
  documented exact outputs, aggregate means, missing values, aliases, and ID rules.
- Added a direct “Get started” navigation link and grouped reference functions by
  task. Kept the existing pkgdown theme and logo, with a compact logo size.
- Made long tables scroll within their containers and fixed mobile sidebar
  overflow. Reviewed the homepage, guide, model reference, and prediction help at
  1280px and 390px widths. All screenshots have alternative text.
- Fixed a broken internal Coh-Metrix link. The rendered site has 25 HTML pages;
  internal links and anchors were checked locally with no broken targets. A
  GitHub-flavored Markdown preview and the standalone vignette were also
  reviewed; long inline R calls wrap on narrow screens.
- Updated README and bibliography to Matta, Keller-Margulis, and Mercer (2025),
  *School Psychology, 40*(6), 707–717, and corrected the title to “Improving
  written-expression curriculum-based measurement feasibility with automated
  writing evaluation programs.” Publication details were verified against
  [PubMed](https://pubmed.ncbi.nlm.nih.gov/40111884/), DOI 10.1037/spq0000691.

## Validation and reproduction

Validation used Linux, R 4.6.1, testthat 3.3.2, covr 3.6.5, caret 7.0.1, and
caretEnsemble 4.0.2. The full suite reports 590 passing expectations, with no failures, warnings, or
skipped tests. R CMD check,
including examples and rebuilt vignettes, reports zero errors, warnings, and notes.
The pkgdown site builds successfully. The existing Windows/macOS/Linux CI matrix
was retained; other operating systems were not run locally.

From the repository root, with development dependencies installed:

```sh
Rscript --vanilla -e 'devtools::test()'
Rscript --vanilla scripts/coverage.R /tmp/writeAlizer-coverage.csv
Rscript --vanilla -e 'rcmdcheck::rcmdcheck(args="--no-manual", error_on="warning")'
Rscript --vanilla -e 'pkgdown::build_site(preview=FALSE)'
git diff --check
```

The unrounded final results are saved in [coverage-2026-09-16.csv](coverage-2026-09-16.csv).
The coverage script prints per-file and overall results and optionally writes a
CSV to the supplied path. It reports whether each result meets 95%, without adding
a CI gate. Site building needs internet access for release metadata; package tests
and coverage use deterministic local fixtures, not production model downloads.

## Preserved behavior and remaining limitations

- **Batch-dependent scoring:** Models 2 and 3 standardize using the submitted
  batch. Scores can change with batch composition; one-row or constant-feature
  batches may yield missing values or model errors. This is documented and tested,
  not recalibrated. Changing it requires separate scientific validation.
- **Model validation:** every supported model family and alias is exercised with
  locally constructed fits and variable lists. Production model URLs/checksums
  were checked for registry consistency, but the 38 remote artifacts were not
  downloaded or scientifically revalidated. Live artifact availability and
  compatibility of every historical serialized model remain separate checks.
- **Missing predictions:** aggregate means continue to omit missing components;
  entirely missing rows yield NaN. GAMET-derived scores and model predictions are
  not clipped or rounded. These existing choices are described for users.
- **Cache identity:** filenames are cache keys. A different URL alone does not
  refresh an existing file; callers should supply a checksum or clear the cache.
  Local mock artifacts intentionally bypass production checksums.
- **Dependency reporting:** `model_deps()` reports all Suggests and optional added
  requirements, including development tools. It checks package availability,
  not version constraints. Runtime model loading checks the loaded fits' packages.
- **Historical research summaries:** detailed published model tables were retained.
  The contradictory claim that all small/negative algorithm weights were removed
  was replaced with a description consistent with the displayed coefficients.
  This audit does not independently re-estimate those historical models.
